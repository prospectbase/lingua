# @prospectbase/lingua

Native Node.js bindings for [lingua](https://github.com/pemistahl/lingua-rs), the language detector built for short text: single words, names, job titles. This package wraps the Rust library, lingua 1.8.0, compiled with [napi-rs](https://napi.rs).

- **Native, not WASM.** The language models are compiled into the binary, and the operating system pages in only the parts a detector reads. A Node process running two detectors peaks at about 90 MB, Node's own ~50 MB included. A WASM build of the same lingua holds every model in memory at once, about 900 MB.
- **All 75 languages** are in every build. Languages are named by their ISO 639-1 code, in and out.
- **Prebuilt** for macOS (arm64, x64) and Linux glibc (x64, arm64). There's no compile step when you install.

## Install

```bash
npm install @prospectbase/lingua
```

npm installs only the binary for your platform, as an optional dependency.

## Use

```ts
import { LanguageDetector, supportedLanguages } from "@prospectbase/lingua";

// Choose between as few languages as you can: lingua is more accurate on short
// text when it has fewer candidates.
const detector = new LanguageDetector(["en", "es", "ca"], { minimumRelativeDistance: 0.1 });

detector.detect("Supervisor de operaciones");
// { language: "es", confidence: 0.77 }

await detector.detectMany(["Head of Sales", "Senior 3D Animator"]);
// [{ language: "en", confidence: 0.59 }, { language: "en", confidence: 0.64 }]

detector.confidenceValues("Profesor de arte");
// [{ language: "es", confidence: 0.75 }, { language: "ca", confidence: 0.16 }, { language: "en", confidence: 0.08 }]

// When the top two languages are closer than minimumRelativeDistance, no
// language is named.
new LanguageDetector(["en", "it"], { minimumRelativeDistance: 0.1 }).detect("Senior 3D Animator");
// { language: null, confidence: 0 }

supportedLanguages(); // ["af", "ar", "az", ...]
```

### `new LanguageDetector(languages, options?)`

`languages` lists ISO 639-1 codes, in any case. An unknown code, an empty list or an out-of-range option throws a JavaScript error. lingua itself would panic and take the process down, so every input is checked first.

| Option | Default | |
|---|---|---|
| `minimumRelativeDistance` | `0` | From 0 to 0.99. How far apart the top two candidates must be before a language is named. Below it, the result is `null` rather than a guess. |
| `lowAccuracyMode` | `false` | Faster, but less accurate on short text. |
| `preloadLanguageModels` | `false` | Load every model when the detector is built instead of on first use. |

### Methods

- **`detect(text)`** returns `{ language, confidence }`. `language` is a code, or `null` when no language could be named. `confidence` is from 0 to 1, relative to the detector's languages, and is 0 when `language` is `null`. It runs on the calling thread.
- **`detectMany(texts)`** returns a promise of the same, one result per text, in order. It runs on libuv's thread pool and spreads the batch across the CPU's cores, so use it for batches.
- **`confidenceValues(text)`** returns every language's confidence, highest first.

## Develop

You need Rust (stable) and Node 22 or later.

```bash
npm ci
npm run build   # release build for this machine: lingua.<platform>.node, index.js, index.d.ts
npm test
```

`index.js` (the loader that picks the platform's binary) and `index.d.ts` are generated by `napi build` from `src/lib.rs`. Commit them whenever the binding's API changes.

A release build compiles every language model in and takes under a minute on an Apple Silicon Mac. The binary is about 290 MB.

## Release

CI (`.github/workflows/CI.yml`) builds and tests every target on each push to `main`. It publishes when the head commit is a version commit:

```bash
npm version patch   # or minor / major; commits "x.y.z"
git push
```

Publishing needs two things set up once:

1. The `prospectbase` organisation on npmjs.com, which owns the `@prospectbase` scope.
2. An npm automation token in the repository secret `NPM_TOKEN`.

`npm publish` runs `napi prepublish`. That publishes one package per platform (`@prospectbase/lingua-darwin-arm64`, `-linux-x64-gnu`, …) and points the main package's `optionalDependencies` at them.

### Upgrading lingua

Bump the version pinned in `Cargo.toml` (`lingua = "=x.y.z"`), rebuild, run the tests, and release. Read lingua's release notes first: a release can add languages (the next one adds Luxembourgish), which changes `supportedLanguages()` and the test that counts them.
